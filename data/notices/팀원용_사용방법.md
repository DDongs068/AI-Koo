# 서울 버스 우회·무정차 공지 CSV — 팀원용 사용방법

TOPIS(서울시 교통정보) 공지를 5분~3시간마다 자동 수집해 만든 표준 CSV입니다. 이 문서는 **데이터를 가져다 쓰는 사람**을 위한 설명입니다.

## 1. 어디서 받나

저장소 `https://github.com/DDongs068/AI-Koo` 의 `data/notices/` 폴더 (공개 저장소, 로그인 불필요).

| 파일 | 용도 |
|---|---|
| **`topis_v1_active.csv`** | **지도·길찾기에 쓰는 파일.** 이것만 쓰면 됩니다. |
| `topis_v1_hold.csv` | 자동 검사를 통과 못 해 뺀 행(노선 데이터에 없는 정류소 등). 참고용 |
| `topis_v1_우회경로.csv` | 우회 경로 지점(순서대로). 참고용 |

고정 주소: `https://raw.githubusercontent.com/DDongs068/AI-Koo/main/data/notices/topis_v1_active.csv`

### 받는 방법 3가지
1. **브라우저**: 위 폴더에서 파일을 눌러 오른쪽 위 *Download raw file*.
2. **스크립트(권장)**: `python fetch_notices.py` → `./notices/topis_v1_active.csv` 로 받고 행 수·열·정류소ID를 검사해 줍니다. `--all` 이면 hold·우회경로도 받습니다. `--load-v1 --engine-dir engine --db cityflow.db` 를 붙이면 받은 뒤 엔진 적재(`python -m cityflow load-v1 …`)까지 실행합니다.
3. **git**: `git clone https://github.com/DDongs068/AI-Koo` 후 `git pull` 할 때마다 최신.

PowerShell 한 줄: `Invoke-WebRequest https://raw.githubusercontent.com/DDongs068/AI-Koo/main/data/notices/topis_v1_active.csv -OutFile topis_v1_active.csv`

### 공지 원본 첨부(PDF 등)가 필요할 때
`data/notices/originals/` 에 CSV에 반영된 공지의 첨부 원본이 있습니다. `index.csv` 에 공지마다 **종류**(우회 / 무정차 / 우회+무정차)와 첨부 파일 경로가 적혀 있습니다.
- 우회 지도(HTML)가 필요한 공지 = 종류가 '우회' 또는 '우회+무정차'.
- 첨부가 없는 공지(글로만 적힌 공지)는 폴더가 없고 첨부파일 칸이 비어 있습니다.
- 지난 행사 파일은 하루 뒤 자동으로 지워집니다.

## 2. 언제 바뀌나 · 어떻게 교체하나

- 수집 PC가 켜져 있는 동안 주기적으로(시험 중 5분, 운영 3시간) 갱신하고, **바뀐 내용이 있을 때만** 저장소에 올립니다. PC가 꺼져 있으면 마지막 파일이 그대로 남습니다.
- 파일은 **그 시점에 유효한 공지 전체**입니다. 행사가 끝나고 1일이 지나면 빠지고, 앞으로 7일 안에 시작하는 공지까지 들어옵니다. 공지가 수정(버전 증가)·취소되면 그에 맞게 바뀝니다.
- 그래서 새 파일을 받으면 **이전 파일 위에 덧붙이지 말고 통째로 교체**하세요.

## 3. 열 설명 (active, 33개)

한 행 = **(노선, 정류소) 한 개가 그 날짜·시간에 영향을 받는다**는 뜻입니다. 열 이름으로 읽으세요(순서에 의존하지 말 것).

| 열 | 의미 |
|---|---|
| `공지ID`, `공지제목`, `원문링크`, `버전` | 출처 공지. 같은 내용의 공지가 여러 건이면 번호가 큰 공지 하나로 합쳐지고 `비고`에 "동일 내용 공지 병합: …"이 적힙니다 |
| `공지상태` | 유효 (취소된 공지는 파일에서 빠집니다) |
| `노선번호` | 노선 데이터의 노선명과 같은 표기(예: `162`, `N72`, `강남06-1`, `서울01퇴근`) |
| `방향`, `방향근거` | 방향이 공지에 적혀 있으면 값, 아니면 비어 있고 `방향근거`에 "공지 ID로 특정" 등이 적힙니다 |
| `우회일자` | 시작 날짜(YYYY-MM-DD) |
| `시작시각`, `종료시각` | HH:MM. **종료가 시작보다 이르면 다음 날 종료**(예: 22:00~05:00, `비고`에 "다음날 종료") |
| `종료시각구분` | `지정` = 종료시각이 적혀 있음 / `통제해제시` = 종료시각이 비어 있고 "통제가 풀릴 때까지" |
| `기존`, `우회` | 안내문의 기존·우회 경로 글(참고용, 정리되지 않은 원문일 수 있음) |
| `무정차정류소` | 정류소 이름 |
| `정류소ID` | **5자리 ARS 번호 — 문자열로 읽으세요**(앞의 0 보존, 예: `01732`) |
| `정류소순번` | 그 노선의 정류소 순번. 비어 있으면 판정에 쓰지 마세요(방향이 불확실한 행) |
| `확인상태` | `확인` / `확인 필요`(공지 글만으로 100% 확정하지 못한 행, 예: 노선을 정류소로 역추적한 경우) |
| `NODE_ID`, `ARS_ID_노선데이터`, `정류소명_노선데이터`, `X좌표`, `Y좌표` | 노선 데이터에서 찾은 값(경도 X, 위도 Y) |
| `매칭결과` | active에는 `일치`, `순번 보완`만 들어옵니다 |
| `비고` | 사람이 읽는 참고 문구 |

## 4. 읽을 때 주의

- CSV는 UTF-8(BOM 포함)입니다. `pandas.read_csv(..., dtype=str, encoding="utf-8-sig")` 처럼 **전부 문자열로** 읽으세요.
- **엑셀로 열어 저장하지 마세요.** 정류소ID의 앞자리 0이 지워져 깨집니다. 열어 보기만 할 때도 저장은 하지 말고 닫으세요(`fetch_notices.py` 가 이 문제를 검사해 줍니다).
- `확인 필요` 행도 파일에 들어 있습니다. 지도에는 통제로 보여 주되 "확인 필요"로 구분해 표시하는 것을 권합니다.

## 5. 알려진 한계

- 정류소를 **이름으로만** 적은 공지는 번호를 특정할 수 없어 파일에 들어가지 않습니다(예: 6339 여의도 집회). 수집기의 `summary.txt` 에는 "처리 못 함"으로 남습니다.
- 임시정류장(예: "무대 뒤편")은 위치를 알 수 없어 담지 않습니다.
- 노선 데이터가 2026-09-02 기준이라, 그 뒤 새로 생긴 정류소는 `hold`(노선 없음)로 갑니다.
- 글에 노선이 없는 무정차 공지(집회 등)는 그 정류소를 지나는 **모든 노선**으로 간주했습니다(`확인 필요`).
