# Route B — 길이 바뀌어도, 답은 있다

> 2026 서울 청년 AI 해커톤

행사로 길이 막히는 날, **내가 타려는 버스가 어느 정류소에 서지 않는지**와 **그래서 어디서 어떻게 가면 되는지**를 알려 줍니다.

서울시는 마라톤·집회 때 버스 무정차·우회 공지를 냅니다. 그런데 그 공지는 194쪽 PDF에 노선과 정류소 이름으로만 적혀 있어, 정작 버스를 기다리는 사람이 "내 정류소에 오늘 버스가 서나"를 알기 어렵습니다. Route B는 그 공지를 정류소 **순번** 단위로 정규화해, 출발지·도착지·시각만 넣으면 통제를 반영한 경로를 돌려줍니다.

---

## 바로 실행하기

```bash
git clone https://github.com/DDongs068/AI-Koo && cd AI-Koo
KAKAO_REST_KEY=<카카오 REST 키> node backend/server/web.js
# → http://localhost:8080  (Node 18+, 설치할 의존성 없음)
```

키는 [카카오 디벨로퍼스](https://developers.kakao.com)에서 앱을 만들면 **REST API 키**로 발급됩니다. 장소 검색·도보 경로·우회선 계산에 씁니다.

키 없이도 실행됩니다. 이때 장소 검색이 막히므로 지도를 **마우스 오른쪽 클릭**해 출발지·도착지를 찍으면 됩니다. 통제 판정은 키와 무관하게 그대로 동작하고, 우회선만 직선으로 근사됩니다.

기동하면 우회선 계산이 먼저 돌아 **수 분**이 걸립니다. 그동안 들어온 요청은 기다렸다가 응답하므로 그냥 두면 됩니다. 진행 상황은 `GET /health` 에서 `status`가 `ready`가 되는지로 봅니다.

```bash
curl localhost:8080/health
# {"status":{"nov+subway":"ready"},"busRoutes":634,"subwayRoutes":23, ...}
```

실시간 버스 도착 정보까지 보려면 `SEOUL_BUS_KEY`(서울 열린데이터광장)를 함께 넣습니다. 없으면 그 칸만 "미제공"으로 표시됩니다.

엔진 데이터는 **2026-11-01**(JTBC 서울마라톤)과 **2026-03-15**(서울마라톤) 두 행사 기준입니다. 그 날짜로 넣어야 통제가 반영됩니다.

## 무엇을 풀었나

### 1. 공지를 "판정할 수 있는 데이터"로
공지는 사람이 읽는 문서입니다. 정류소 이름이 노선 데이터와 다르게 적히고(`한국은행(스프라지르명동)`), 방향이 화살표로만 표시되고, 종료시각이 비어 있기도 합니다.

- **이름이 아니라 순번으로 판정**합니다. 이름은 표기가 흔들리지만 노선 내 순번은 흔들리지 않습니다.
- ARS 번호는 **방향까지 구분**합니다(종로4가.종묘 = `01018` 여의도방향 / `01017` 망우동방향). ARS로 맞추면 방향이 따라옵니다. 공지의 방향 칼럼은 2,729행 중 1,246행이 "화살표 추정"이라 근거를 함께 보관합니다.
- 순번을 특정하지 못한 행은 **판정에서 뺍니다**(`topis_v1_hold.csv`). 공지에 없다는 것이 정상 운행의 보증은 아니므로, 경고로만 보여 줍니다.

### 2. 역할에 따라 다르게 판정
같은 "무정차"도 그 정류소가 내 여정에서 무슨 역할인지에 따라 영향이 다릅니다.

| 역할 | 무정차일 때 | 처리 |
|---|---|---|
| 타는 정류소 | 버스를 아예 못 탐 | 치명적 — 다른 승차 지점·노선 탐색 |
| 내리는 정류소 | 목적지에서 못 내림 | 치명적 — 다른 하차 지점 탐색 |
| 지나가는 정류소 | 그냥 통과, 우회로 늦어짐 | 지연으로 반영(추정) |

### 3. 통제를 반영한 재탐색
`normalRoute`(통제가 없었다면 최적)와 `candidates`(통제 반영 상위 3개)를 **함께** 돌려줍니다. 사용자가 평소 타던 길이 왜 안 되는지, 대신 무엇을 타야 하는지를 나란히 비교할 수 있습니다.

### 4. 우회 구간을 실제 도로 모양으로
정류소를 직선으로 이으면 선이 건물을 가로지릅니다. 그래서 신뢰도 순으로 좌표를 조립합니다.

1. **같은 길을 같은 방향으로 달리는 다른 노선의 공식 경로**를 구간만 잘라 차용 — 가장 믿을 만합니다
2. 자기 노선 공식 경로를 역방향으로 재사용 / 교차로 좌표 직선
3. 카카오 길찾기 — 가장 약하므로 "추정"으로 표시

화면은 이 구간을 **빨간 점선 + "우회" 배지**로 정상 운행과 구분합니다.

  server/web.js             화면 서빙 + POST /route  ← 실행 지점
  server/server.js          엔진 전용 원본 서버
  data/cityflow-data.json   공지 115노선 + 우회 설정 109개
  data/extra-routes.json    통제 없는 519노선 (합계 634노선)

## 기술 선택의 이유

**엔진에 의존성을 두지 않았습니다.** `node backend/server/web.js` 하나로 뜹니다. 설치 단계에서 막히지 않게 하려는 의도이고, 데이터도 JSON 파일이라 DB 설치가 필요 없습니다.

**판정 데이터와 조회 데이터를 분리했습니다.** 공지 정규화·검증은 SQLite에서 하고(ERD 1단계), 결과를 JSON으로 굳혀 엔진이 메모리에 올립니다(ERD 2단계). 조회마다 순번을 다시 맞추지 않아 응답이 빠릅니다.

**좌표의 출처를 응답에 남깁니다.** 어느 구간이 공식 형상이고 어느 구간이 길찾기 추정인지 화면에서 구분됩니다. 추정을 사실처럼 보여 주지 않으려는 것입니다.

## 한계 (의도적으로 남긴 것)

- **우회 도로의 실제 정차 여부는 모릅니다.** 194쪽 공지에 임시정류소 표기가 0건이고, 우회경로 `정차` 지점 258개 중 256개가 원래 노선 위였습니다. 그래서 우회선은 **표시용**이고 판정 근거로 쓰지 않습니다.
- 소요 시간·우회 지연·미기재 종료시각은 **추정값**입니다.
- 자동 생성 우회 설정 **96개 노선**은 검수 전이라 결과에 "확인 필요"로 표시합니다([backend/data/auto_generated_routes.txt](backend/data/auto_generated_routes.txt)).
- 705번은 우회선 계산 실패(정류소 39·40 누락)로 정상 운행 처리되며 `notes.detourFailed`에 남습니다. 111·241·2016번은 공지 CSV와 우회 설정이 다릅니다.
- 엔진 데이터는 2026-11-01·2026-03-15 두 행사 기준입니다. 다른 날짜는 공지 수집 후 데이터 재생성이 필요합니다.
- 지하철은 1~8호선만이며 통제 영향 대상이 아닙니다. 9호선·신분당선·공항철도 등은 미포함입니다.
