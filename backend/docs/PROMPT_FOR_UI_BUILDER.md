# 받는 분이 AI(Claude 등)에게 붙여넣을 프롬프트
(아래 박스 내용을 복사해서 프롬프트로 보내고, 이 폴더의 파일들을 첨부하세요. 첨부: engine/cityflow-core.js, server/server.js, data/cityflow-data.json, docs/API.md, docs/known_issues_and_style.md, 그리고 우리 UI 코드)

---
우리 서비스는 이미 만들어진 UI가 있고, 여기에 "출발지·도착지·출발시각을 입력하면 서울 행사(마라톤 등) 버스 무정차·우회를 반영한 대중교통 경로를 찾아 보여주는" 기능을 추가하려고 해. 경로 계산 엔진은 다른 사람이 만든 것을 그대로 쓰고, 나는 UI 쪽만 우리 방식으로 만들면 돼. 첨부 파일을 읽고 아래대로 진행해 줘.

## 첨부 파일
- engine/cityflow-core.js : 경로 엔진(화면·지도 의존 없음). 수정하지 말고 그대로 사용
- server/server.js : 엔진을 HTTP API로 감싼 서버(Node 18+, 의존성 없음). POST /route
- data/cityflow-data.json : 노선·정류소·우회 설정 데이터(약 6MB). 이 형태 그대로 엔진에 넘겨야 함
- docs/API.md : 요청·응답 명세, 한계. 반드시 먼저 읽을 것
- docs/known_issues_and_style.md : 알려진 데이터 문제
- (우리 UI 코드는 따로 첨부/설명할게)

## 해 줘야 할 일
1. 먼저 우리 UI 코드(프레임워크, 지도 라이브러리, 서버 구조)를 파악하고, 통합 계획을 짧게 요약해 줘. 모호한 부분은 최대 3개만 물어봐.
2. 엔진 서버를 우리 백엔드에 붙이는 방법 제안·구현: (a) 별도 프로세스로 띄우고 우리 백엔드가 /route 를 호출 / (b) 우리 Node 백엔드에 코드를 합치기. 우리 구조에 맞는 쪽을 골라 이유를 설명해 줘. 카카오 REST 키는 환경변수 KAKAO_REST_KEY 로만 쓰고 코드에 박지 마.
3. 데이터 저장: data/cityflow-data.json 의 routes/headway(거의 안 바뀜)와 scen.<행사>(행사마다 바뀜)를 우리 저장소에 맞게 어떻게 둘지 정하고, 엔진에 넘기기 직전에 원래 JSON과 같은 형태로 합쳐 주는 로더를 만들어 줘. (우선은 JSON 파일 그대로 읽는 것으로 시작해도 됨)
4. 화면: 출발지·도착지·출발시각 입력 → /route 호출 → 결과 표시. 표시 방식은 우리 UI의 기존 디자인·컴포넌트 규칙을 따라 줘. 최소한 보여줄 것:
   - 정상 운행 경로(normalRoute)와 우회 반영 경로 후보(candidates) 구분
   - 후보별 소요 시간·도착 시각, 구간별(도보/버스 노선, 승하차 정류소, 환승)
   - 우회 구간(detour:true)과 정차하지 않는 정류소(skippedSeqs)가 구분되게
   - 지도가 있으면 geometry 좌표로 경로를 그리되, 도보는 점선 등 버스와 구별
   - 추정값은 "추정", 자동 생성 우회 설정이 들어간 결과는 "확인 필요" 문구
5. 로딩·오류 처리: 서버 시작 후 우회 선 계산에 수 분 걸릴 수 있으니(GET /health 의 status) 준비 중 상태를 표시하고, found:false·error·notes.detourFailed 를 사용자에게 이해되는 문구로 처리해 줘.
6. 확인: 첨부된 사례(data/cityflow-cases.json)의 출발·도착 좌표 한두 개로 /route 를 실제 호출해 응답을 화면에 연결했는지 확인하고, 확인한 것과 확인하지 못한 것을 나눠서 알려 줘.

## 지켜 줄 것
- 엔진(cityflow-core.js)과 데이터 의미는 바꾸지 마. 문제가 보이면 고치지 말고 나에게 알려 줘.
- 카카오 키 등 비밀값을 코드·응답에 노출하지 마.
- 변경한 파일 목록과 실행 방법을 마지막에 정리해 줘.
